# Plan 6.2: Hardcoded Secrets & ENV Handlers

<objective>
Eradicate defaults that allow unconfigured servers to spin up using identical master passwords / JWTs, making them prime targets for botnets.

Purpose: Forces Dev/Prod environments to actively manage and provision credentials, failing loudly otherwise.
</objective>

<tasks>

<task type="auto">
  <name>Remove YAML Plaintext Secrets</name>
  <files>configs/master_settings.yml</files>
  <action>
    Replace hardcoded passwords for Redis and PostgreSQL with ENV format tokens: ${REDIS_PASSWORD} and ${DB_PASSWORD}.
    AVOID changing the structural yaml keys.
  </action>
  <verify>grep "\${REDIS_PASSWORD}" configs/master_settings.yml</verify>
  <done>Redis and PostgreSQL keys pull exclusively from OS vars</done>
</task>

<task type="auto">
  <name>Terminate JWT Sandbox</name>
  <files>docker-compose.yml, searchboost_api/src/app.js</files>
  <action>
    In docker-compose.yml, replace JWT_SECRET=${JWT_SECRET:-...} with JWT_SECRET=${JWT_SECRET:?JWT_SECRET must be set}.
    In app.js (or index.js where the express app lives), throw an explicit Error process.exit(1) on boot if process.env.JWT_SECRET is entirely undefined or empty.
  </action>
  <verify>cat searchboost_api/src/app.js</verify>
  <done>Compose halts if unassigned. Process throws if undefined.</done>
</task>
