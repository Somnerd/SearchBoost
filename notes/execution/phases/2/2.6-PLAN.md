# Plan 2.6: Search Page (Core Product UI)

<objective>
Build the main search experience — the reason SearchBoost exists. Users submit
queries, the app enqueues them via the Node.js proxy to the Warden, polls for
results, and displays the AI-synthesized answer. Multi-turn conversation is
supported (each new query in the same session builds on prior context).

Design: Central search bar with glow on focus, results displayed in a glass card
below with typewriter-style reveal animation as text arrives. Chat history shown
as a left sidebar for conversation context.

Purpose: This is the product. It must feel fast, clean, and intelligent.
Output: Fully functional search page integrated with the real backend.
</objective>

<task type="auto">
  <name>ResultDisplay component + Search page with polling</name>
  <files>
    searchboost_ui/src/components/ResultDisplay.jsx
    searchboost_ui/src/pages/Search.jsx
  </files>
  <action>
    `ResultDisplay.jsx`:
    Props: { result (string), loading (bool), error (string|null) }
    - loading=true: animated pulsing dots ("Thinking...") with dot-dot-dot CSS animation
    - error: red error card with the error message
    - result: render in a glass-card. Use `white-space: pre-wrap` so paragraphs wrap correctly.
      Add a subtle "AI Response" label in text-muted above the result.
      Add fade-in animation when result first appears.
    - No result + no loading + no error: empty (page starts blank)

    `Search.jsx` (the main page):
    Layout: full page flex column. NavBar at top (already in App.jsx).
    Below NavBar: centered container (max-width 800px):
      - Welcome heading: "Hello, {username}" in 2rem
      - Subtitle: "What do you want to know today?" in text-muted
      - SearchBar component
      - ResultDisplay component below it
      - Conversation history panel: small cards above the search bar showing prior
        Q&A pairs in this session (stored in local component state as array of
        { query, result } objects)

    State: { loading, result, error, conversationHistory[] }

    handleSearch(query) async:
    1. Set loading=true, clear error, clear result
    2. POST /api/search/enqueue → { id: job_id }
    3. Start polling: setInterval every 2000ms:
       GET /api/search/result/{job_id}
       → status="pending": continue polling
       → status="complete": clearInterval, set result, push to conversationHistory,
         loading=false
       → error/timeout: clearInterval, set error message, loading=false
    4. Set a max-poll timeout of 240s (120 polls × 2s) then error "Request timed out"

    Conversation history display:
    - Collapsible list above SearchBar
    - Each entry: small glass-card with "Q: {query}" and "A: {first 100 chars}..."
    - "New conversation" button that clears history (client-side only — Postgres history
      remains; new session = same user but fresh UI context)

    AVOID: Using setInterval without cleanup — clear on component unmount and on
    each new search start to prevent stale intervals stacking.
    AVOID: Polling forever — the 240s timeout prevents zombie intervals.
  </action>
  <verify>
    Log in → /search → type "what is the capital of France" → submit
    → loading indicator shows → after Warden/Worker process → result appears
    → type follow-up "and what is its population" → result uses prior context
  </verify>
  <done>

    Results display correctly.
    Conversation history shows Q&A pairs.
    No polling leaks (no duplicate requests on re-render).
  </done>
</task>
