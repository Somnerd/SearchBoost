# Plan 2.5: Login + Register Pages

<objective>
Build the Login and Register pages. These are the first thing users see — they
must be visually stunning and functionally solid. Glass card on animated dark background,
smooth field interactions, inline error handling.

Purpose: User-facing entry point to the product. First impression matters.
Output: Two fully functional auth pages that integrate with the auth API.
</objective>

<context>
Load for context:
- searchboost_ui/src/index.css  (design system variables)
- searchboost_ui/src/api/client.js  (axios instance)
- searchboost_ui/src/context/AuthContext.jsx  (useAuth hook, login())
- .gsd/phases/2/2.2-PLAN.md  (endpoint shapes + error codes)
</context>

<tasks>

<task type="auto">
  <name>Login page</name>
  <files>searchboost_ui/src/pages/Login.jsx</files>
  <action>
    Centered layout — full viewport height, flex center.
    Background: deep navy with 3 large blurred radial gradient orbs (position: fixed, z-index: -1)
    in accent blue, purple, and teal, slowly drifting via CSS animation (keyframes translateX/Y,
    60s infinite alternate ease-in-out). Creates a living ambient background.

    Glass card (.glass-card) containing:
    - "SearchBoost" logo/wordmark at top in accent color, 1.8rem bold
    - H1: "Welcome back" 1.4rem
    - Subtitle: "Sign in to your account" in text-muted
    - Username input (id="login-username") with label
    - Password input (id="login-password") type=password with label
    - Error message area: red text below inputs, only shown when error exists
    - Submit button (.btn-primary, full width): "Sign In" | loading state: "Signing in..."
    - Link to /register: "Don't have an account? Register"

    State: { username, password, error, loading }

    Submit handler:
    1. Validate: both fields non-empty → set error if not
    2. Set loading=true, clear error
    3. POST /api/auth/login via client.js
    4. On 200: call login(responseData) from useAuth, navigate("/search")
    5. On 401: set error "Invalid username or password"
    6. On any other error: set error "Something went wrong. Please try again."
    7. Finally: loading=false

    AVOID: Using alert() for errors.
    AVOID: Navigating before login() is called — auth context must update first.
    Apply .page-enter CSS class for fade-in animation on mount.
  </action>
  <verify>
    - Open /login, submit empty form → inline validation error
    - Submit wrong credentials → "Invalid username or password" below form
    - Submit correct credentials → redirected to /search, NavBar shows username
  </verify>
  <done>All 3 verify scenarios pass, no console errors, visually matches design spec</done>
</task>

<task type="auto">
  <name>Register page</name>
  <files>searchboost_ui/src/pages/Register.jsx</files>
  <action>
    Same ambient background as Login page (extract orbs to a shared CSS class `.bg-orbs`
    or duplicate the fixed orb divs — either is fine).

    Glass card containing:
    - "SearchBoost" wordmark
    - H1: "Create account"
    - Username input (id="register-username")
    - Password input (id="register-password") type=password
    - Confirm password input (id="register-confirm") type=password
    - Client-side validation:
      * Username: 3-32 chars, alphanumeric + underscore only
      * Password: min 8 chars
      * Passwords must match
    - Error area (same pattern as Login)
    - Submit button: "Create Account" | loading: "Creating account..."
    - Link to /login: "Already have an account? Sign in"

    Submit handler:
    1. Run all validations, show first failing one
    2. POST /api/auth/register
    3. On 201: immediately POST /api/auth/login with same credentials
    4. On login 200: login(userData), navigate("/search")
    5. On 409: error "Username already taken"
    6. On other error: generic error message

    AVOID: Showing a "now go log in" flow — auto-login after register for best UX.
    AVOID: Sending confirm password to the server — it's client-side only validation.
  </action>
  <verify>
    - Register with mismatched passwords → client-side error, no request sent
    - Register with existing username → 409 "Username already taken"
    - Register with new credentials → auto-logged in, redirected to /search
  </verify>
  <done>
    Registration auto-logs in and redirects to /search.
    User visible in NavBar immediately after registration.
  </done>
</task>
