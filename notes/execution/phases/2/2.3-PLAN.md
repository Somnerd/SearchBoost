# Plan 2.3: Search Proxy + Admin API Routes

<objective>
Add the two remaining route groups: search (proxies to Warden) and admin
(user management + system health). Both require authentication.

Key design: session_id is derived from req.user.username so all searches
from a logged-in user automatically link to their conversation history
in the existing HistoryService / ConversationTurn table.

Purpose: Give the frontend all the API surface it needs.
Output: Full REST API ready for the React frontend.
</objective>

<context>
Load for context:
- searchboost_api/src/middleware/auth.js
- searchboost_api/src/db/users.js
- .gsd/ARCHITECTURE.md  (Warden endpoints: /enqueue, /results/:id, /health)
</context>

<tasks>

<task type="auto">
  <name>Search proxy routes</name>
  <files>searchboost_api/src/routes/search.js</files>
  <action>
    Install axios: `npm install axios` (in searchboost_api/)

    Create Express Router. Mount in app.js as `/api/search`.
    All routes apply verifyToken middleware.

    POST /enqueue:
    - Body: { query, options? }
    - Derive session_id = `SB-SESSION-${req.user.username}`
      (matching the format the Worker expects: rsplit(':',1)[0] = session_id)
    - Forward to axios.post(`${WARDEN_URL}/enqueue`, {
        query,
        session_id,
        options: options || {}
      })
    - Return Warden's response (status + job_id) to client
    - On Warden error (circuit open, 503): propagate status + message

    GET /result/:job_id:
    - Forward to axios.get(`${WARDEN_URL}/results/${req.params.job_id}`)
    - Return Warden's response ({ status: "pending" } or { status: "complete", result })
    - On timeout/error: return 503 { error: "Could not reach Warden" }

    AVOID: Passing Authorization headers to the Warden — it doesn't understand them.
    The Warden is internal (Docker network), auth is handled at the Node.js layer.

    AVOID: Exposing WARDEN_URL in any client response — it's an internal Docker hostname.
  </action>
  <verify>
    Login, grab cookie, then:
    curl -X POST localhost:3001/api/search/enqueue -b /tmp/cookies.txt \
      -H "Content-Type: application/json" -d '{"query":"test"}'
  </verify>
  <done>Returns { status: "queued", id: "SB-SESSION-username:uuid" } from Warden</done>
</task>

<task type="auto">
  <name>Admin routes: user management + system health</name>
  <files>searchboost_api/src/routes/admin.js</files>
  <action>
    Create Express Router. Mount in app.js as `/api/admin`.
    All routes apply verifyToken + requireAdmin middleware (chain both).

    GET /users:
    - listUsers() from db/users.js
    - Return array of { id, username, role, created_at }

    PATCH /users/:id/role:
    - Body: { role } — validate role is "user" or "admin" only
    - Prevent admin from demoting themselves (req.user.id === parseInt(id) → 400)
    - updateRole(id, role)
    - Return updated user object

    DELETE /users/:id:
    - Prevent admin from deleting themselves → 400
    - deleteUser(id)
    - Return 200 { message: "User deleted" }

    GET /health:
    - Ping Warden: axios.get(`${WARDEN_URL}/health`, { timeout: 3000 })
    - Ping DB: pool.query("SELECT 1")
    - Return {
        warden: { status: "healthy"|"unreachable", circuit_breaker: "open"|"closed" },
        database: { status: "healthy"|"unreachable" },
        timestamp
      }
    - Never throw — catch each independently and report partial health.

    AVOID: Allowing role values other than "user" or "admin" — validate strictly.
    AVOID: Letting an admin delete/demote themselves — would lock out the system.
  </action>
  <verify>
    curl -X GET localhost:3001/api/admin/users -b /tmp/admin_cookies.txt
    curl -X GET localhost:3001/api/admin/health -b /tmp/admin_cookies.txt
  </verify>
  <done>
    /users (as admin) → 200 array
    /users (as regular user) → 403
    /health → 200 with warden + database status objects
  </done>
</task>
