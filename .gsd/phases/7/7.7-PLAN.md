# Plan 7.7: Horizontal Worker Scaling & Distributed Observation

## Objective
Enable horizontal scaling of the Python worker service by removing hardcoded container names and updating the Warden to monitor logs from multiple worker instances using Docker labels.

## Context
- .gsd/SPEC.md
- docker-compose.yml
- searchboost_warden/src/observer.rs
- searchboost_warden/src/configurator.rs
- searchboost_warden/src/main.rs

## Tasks

<task type="auto">
  <name>Modify docker-compose.yml for Scaling</name>
  <files>docker-compose.yml</files>
  <action>
    - Remove `container_name: sb_worker` from the `worker` service.
    - Add a label `com.searchboost.service=worker` to the `worker` service.
    - This allows running multiple worker instances without name collisions.
  </action>
  <verify>docker compose config | grep "com.searchboost.service=worker"</verify>
  <done>Worker service has the required label and no fixed container name.</done>
</task>

<task type="auto">
  <name>Update Warden Configurator for Label Discovery</name>
  <files>searchboost_warden/src/configurator.rs</files>
  <action>
    - Update `ObserverSettings` struct to include `container_label: Option<String>`.
    - In `Settings::load`, check for `WARDEN__OBSERVER__CONTAINER_LABEL` environment variable.
  </action>
  <verify>cargo check --manifest-path searchboost_warden/Cargo.toml</verify>
  <done>ObserverSettings includes container_label field.</done>
</task>

<task type="auto">
  <name>Implement Multi-Container Log Observation</name>
  <files>
    searchboost_warden/src/observer.rs
    searchboost_warden/src/main.rs
  </files>
  <action>
    - Modify `observer.rs` to use `docker.list_containers` to find all containers with the specified label if `container_label` is provided.
    - If `container_label` is used, spawn a log stream for EACH discovered container.
    - Update `main.rs` to pass the label from settings to the observer.
  </action>
  <verify>cargo build --manifest-path searchboost_warden/Cargo.toml</verify>
  <done>Warden can monitor logs from multiple containers identified by a label.</done>
</task>

## Success Criteria
- [ ] Docker Compose allows scaling workers (e.g., `docker compose up --scale worker=2`).
- [ ] Warden successfully starts and identifies multiple worker containers by label.
- [ ] Logs from all worker instances are aggregated into `service_observation.log`.
