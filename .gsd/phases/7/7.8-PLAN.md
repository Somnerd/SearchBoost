# Plan 7.8: Dynamic LLM Model Selection

## Objective
Enable runtime selection of the LLM model used for research and optimization tasks by allowing the UI/API to pass a model name that overrides the default configuration.

## Context
- .gsd/SPEC.md
- searchboost_service/searchboost_src/service.py
- searchboost_api/src/routes/search.js

## Tasks

<task type="auto">
  <name>Enable Model Override in SearchBoostService</name>
  <files>searchboost_service/searchboost_src/service.py</files>
  <action>
    - In `SearchBoostService.__init__`, check if `self.args.model` exists and is not empty.
    - If so, update `self.ai_config.model` with the provided value.
    - This ensures that subsequent AI calls use the user-specified model.
  </action>
  <verify># Manual check or unit test if available</verify>
  <done>SearchBoostService respects the model override from args.</done>
</task>

<task type="auto">
  <name>Update API Search Route to Accept Model</name>
  <files>searchboost_api/src/routes/search.js</files>

    - Include the `model` in the options object sent to the Warden.
  </action>
  <verify>grep "req.body.model" searchboost_api/src/routes/search.js</verify>

## Success Criteria
- [ ] Users can specify a model in the API request (e.g., `{"query": "...", "model": "llama3.1"}`).
- [ ] The worker service correctly identifies and uses the specified model for both optimization and research.
- [ ] System falls back to default model if none specified.
