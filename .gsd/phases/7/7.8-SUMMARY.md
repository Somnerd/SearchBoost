# Phase 7.8 SUMMARY: Dynamic LLM Model Selection

Implemented the ability to override the default LLM model at runtime via the API and service arguments.

## Key Changes

### 1. Service Layer Improvements
- **Model Override**: Updated `SearchBoostService` in `service.py` to check for a `model` argument in the startup parameters. If present, it overrides the default model defined in the AI configuration.

### 2. API Gateway Enhancements
- **Dynamic Enqueueing**: Modified the `POST /api/search/enqueue` route in `search.js` to accept an optional `model` field in the request body.
- **Payload Propagation**: The selected model is merged into the `options` object and sent to the Warden for worker task initialization.

## Verification Requirements
- [x] `SearchBoostService` logic includes `if hasattr(self.args, 'model')`.
- [x] API `/enqueue` route extracts `model` from `req.body`.
- [x] API payload to Warden includes the `model` in `options`.
