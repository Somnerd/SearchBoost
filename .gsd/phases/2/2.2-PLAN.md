# Plan 2.2: Auth Endpoints + JWT Middleware

<objective>
Implement the complete authentication API: register, login, logout, and me.
Passwords are hashed with bcrypt (rounds=12). Sessions use an httpOnly,
SameSite=Strict JWT cookie. Also create the reusable auth middleware that
all protected routes will use.

Purpose: Secure user lifecycle with no plaintext secrets in transit or at rest.
Output: 4 auth endpoints + 2 middleware functions.
</objective>

<task type="auto">
  <name>Auth routes: register, login, logout, me</name>
  <files>searchboost_api/src/routes/auth.js</files>
  <action>
    Create Express Router. Mount in app.js as `/api/auth`.

    POST /register:
    - Body: { username, password }
    - Validate: username 3-32 chars (alphanumeric + underscore), password min 8 chars
    - findByUsername → if exists, return 409 "Username already taken"
    - bcrypt.hash(password, 12)
    - createUser(username, hash)
    - Return 201 { id, username, role }
    AVOID: Returning password_hash in any response, ever.

    POST /login:
    - Body: { username, password }
    - findByUsername → null → 401 "Invalid credentials" (same message as wrong password,
      prevents username enumeration)
    - bcrypt.compare(password, user.password_hash) → false → 401
    - jwt.sign({ id, username, role }, JWT_SECRET, { expiresIn: JWT_EXPIRES_IN })
    - res.cookie("sb_token", token, {
        httpOnly: true,
        sameSite: "strict",
        secure: process.env.NODE_ENV === "production",
        maxAge: 86400000  // 24h in ms
      })
    - Return 200 { id, username, role }

    POST /logout:
    - res.clearCookie("sb_token")
    - Return 200 { message: "Logged out" }

    GET /me:
    - Apply verifyToken middleware
    - Return 200 { id, username, role } from req.user

    AVOID: Using jsonwebtoken synchronous verify without try/catch — throws on invalid token.
  </action>
  <verify>
    curl -X POST localhost:3001/api/auth/register -H "Content-Type: application/json" -d '{"username":"testuser","password":"testpass123"}'
    curl -X POST localhost:3001/api/auth/login ... -c /tmp/cookies.txt
    curl localhost:3001/api/auth/me -b /tmp/cookies.txt
  </verify>
  <done>Register → 201, Login → 200 + Set-Cookie, Me with cookie → 200 user object, Me without cookie → 401</done>
</task>

<task type="auto">
  <name>Auth middleware: verifyToken + requireAdmin</name>
  <files>searchboost_api/src/middleware/auth.js</files>
  <action>
    verifyToken(req, res, next):
    - Read req.cookies.sb_token
    - No token → 401 { error: "Authentication required" }
    - jwt.verify(token, JWT_SECRET) in try/catch
    - TokenExpiredError → 401 { error: "Session expired, please log in again" }
    - Other error → 401 { error: "Invalid token" }
    - Set req.user = decoded payload ({ id, username, role })
    - Call next()

    requireAdmin(req, res, next):
    - Expects verifyToken to have run first (chained)
    - req.user.role !== "admin" → 403 { error: "Admin access required" }
    - Call next()

    Export both. Usage: router.get("/protected", verifyToken, handler)
                         router.get("/admin-only", verifyToken, requireAdmin, handler)

    AVOID: Calling requireAdmin without verifyToken before it — req.user will be undefined.
  </action>
  <verify>curl localhost:3001/api/auth/me (no cookie) → 401 "Authentication required"</verify>
  <done>
    No cookie → 401
    Expired/invalid cookie → 401 with specific message
    Valid cookie, non-admin route → passes
    Valid cookie, admin route, role=user → 403
  </done>
</task>
