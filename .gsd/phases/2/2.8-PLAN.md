<task type="auto">
  <name>Dockerfiles for API and UI</name>
  <files>
    searchboost_api/Dockerfile
    searchboost_ui/Dockerfile
  </files>
  <action>
    `searchboost_api/Dockerfile`:
    ```dockerfile
    FROM node:20-alpine
    WORKDIR /app
    COPY package*.json ./
    RUN npm ci --only=production
    COPY src/ ./src/
    EXPOSE 3001
    CMD ["node", "src/app.js"]
    ```
    Multi-stage not needed for Node.js. Use node:20-alpine for small image.

    `searchboost_ui/Dockerfile` (production build served by nginx):
    ```dockerfile
    # Stage 1: Build
    FROM node:20-alpine AS builder
    WORKDIR /app
    COPY package*.json ./
    RUN npm ci
    COPY . .
    RUN npm run build

    # Stage 2: Serve
    FROM nginx:alpine
    COPY --from=builder /app/dist /usr/share/nginx/html
    COPY nginx.conf /etc/nginx/conf.d/default.conf
    EXPOSE 80
    ```

    Create `searchboost_ui/nginx.conf`:
    ```nginx
    server {
        listen 80;
        root /usr/share/nginx/html;
        index index.html;

        # SPA routing — all paths serve index.html
        location / {
            try_files $uri $uri/ /index.html;
        }

        # Proxy /api requests to the Node.js API service
        location /api {
            proxy_pass http://sb_api:3001;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
    ```
    This nginx config handles both SPA routing AND the /api proxy in production,
    replacing the Vite dev proxy from vite.config.js.

    AVOID: Serving the Vite dev server in production — always use the nginx build.
    AVOID: Forgetting try_files for SPA routing — direct URL access to /search
    would 404 without it.
  </action>
  <verify>
    docker build -t sb_api ./searchboost_api
    docker build -t sb_ui ./searchboost_ui
    Both build without error.
  </verify>
  <done>Both images build successfully. sb_ui image runs nginx on :80.</done>
</task>

<task type="auto">
  <name>Add sb_ui and sb_api to docker-compose.yml</name>
  <files>docker-compose.yml</files>
  <action>
    Add two new services to the existing docker-compose.yml.
    DO NOT modify any existing service definitions.

    ```yaml
    sb_api:
      build: ./searchboost_api
      container_name: sb_api
      env_file: .env
      environment:
        - DB_HOST=sb_db
        - DB_PORT=5432
        - DB_USER=${DB_USER:-searchboost}
        - DB_PASSWORD=${DB_PASSWORD:-searchboost_pass}
        - DB_NAME=${DB_NAME:-searchboost_db}
        - WARDEN_URL=http://sb_warden:14141
        - NODE_ENV=production
      ports:
        - "3001:3001"
      depends_on:
        - db
        - warden
      restart: always

    sb_ui:
      build: ./searchboost_ui
      container_name: sb_ui
      ports:
        - "80:80"
      depends_on:
        - sb_api
      restart: always
    ```

    Both services join the default Docker network automatically, allowing
    sb_api to reach sb_warden and sb_db by container name.

    JWT_SECRET must come from the .env file (user_setup item).

    AVOID: Hardcoding JWT_SECRET in docker-compose.yml — it's a secret.
    AVOID: Exposing sb_db ports beyond localhost if this will be public-facing.
  </action>
  <verify>docker compose up --build -d && curl http://localhost:80 && curl http://localhost:3001/health</verify>
  <done>
    sb_ui serves React app at :80
    sb_api returns healthy at :3001/health
    Existing containers (sb_warden, sb_worker, sb_redis, sb_db, sb_ollama, sb_searxng) still running
  </done>
</task>
