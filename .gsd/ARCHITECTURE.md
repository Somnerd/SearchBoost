# Architecture

> Generated by /map on 2026-03-24

## Overview
SearchBoost is a decentralized, highly-resilient hybrid-AI search engine pipeline. It is architected as an asynchronous distributed system isolating user authorization (Node.js), high-throughput boundary ingress/caching (Rust), intensive LLM background execution (Python), and frontend client rendering (React). It gracefully falls back between local constraints (Ollama) and cloud APIs.

## Components

### React Web Client 
- **Purpose:** Interactive GUI for concurrent search threads and authentications.
- **Location:** `searchboost_ui/`
- **Dependencies:** React, Vite, Axios, React Router.
- **Dependents:** None.

### Node.js REST API 
- **Purpose:** Manages User Identity (JWT), maps database Session Threads, and securely proxies queries avoiding UI direct-to-Rust exposure.
- **Location:** `searchboost_api/`
- **Dependencies:** Express, PG, bcrypt, jsonwebtoken.
- **Dependents:** React UI.

### Rust Warden Proxy
- **Purpose:** Ingress Gateway serving high-speed Semantic Cache lookups natively from Redis avoiding Python VM load. Runs strict `tower_governor` GCRA rate-limiting and Circuit Breaking (`failsafe`) against downstream Python crashes. Monitors Docker execution iteratively.
- **Location:** `searchboost_warden/`
- **Dependencies:** Tokio, Axum, Tower, Failsafe, Bollard.
- **Dependents:** Node.js REST API.

### Python ARQ Worker
- **Purpose:** Consumes queries via Redis queues, executes heavy I/O loops against Ollama for semantic reduction, passes distinct keyword chains to SearXNG, and persists parsed analytical outputs back to PostgreSQL history tables.
- **Location:** `searchboost_service/`
- **Dependencies:** ARQ, Asyncpg, PyYAML, Ollama, OpenAI.
- **Dependents:** Rust Warden (Enqueueing).

## Data Flow
1. User logs in safely interacting with Node.js (`/api`).
2. Search triggers dispatch via `Axios` passing secure JWT token. Node bounds the JWT back to a Postgres session UUID.
3. Node dispatches query strictly formatted to Rust `Warden` on Port 14141.
4. Rust hashes query, checks Redis for semantic cache hits strictly isolated per user mapping. If hit, returns immediately.
5. If miss, routes rate-limited task into Redis ARQ.
6. Python pulls task, aggregates SearXNG metadata, prompts Ollama, maps the result to Postgres, updates the Job ID status to `complete` in Redis.
7. React Client natively polls Warden via Node Proxy receiving the complete answer string.

## Conventions
- **Naming:** Consistent snake_case for services (`sb_warden`, `sb_worker`), kebab-case for generic dependencies (`sb-searxng`).
- **Structure:** Distributed horizontally; each stack possesses explicit `Dockerfiles` natively wrapping runtime limits.
- **Testing:** Driven by functional workflow verifications.
- **Configuration:** Hierarchical YAML fallback logic. `configs/master_settings.yml` -> isolated overrides (`warden.yml`, `worker.yml`).
