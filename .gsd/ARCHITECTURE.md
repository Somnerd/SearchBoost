# Architecture

> Generated by /map on 2026-03-18

## Overview
SearchBoost is an AI-powered semantic search and reliability engine with a distributed microservices architecture. It utilizes a Rust-based Warden to handle incoming API requests and circuit breaking, while a Python-based worker consumes queue jobs to interact with Redis, SearXNG, Ollama, and Postgres.

## Components

### Warden
- **Purpose:** Reliable API gateway built in Rust. Responsible for receiving requests from clients, applying circuit breakers, appending jobs to the Redis queue, and observing Docker logs.
- **Location:** `searchboost_warden/`
- **Dependencies:** `tokio`, `axum`, `redis`, `bollard`, `failsafe`.
- **Dependents:** CLI Clients

### Service Worker
- **Purpose:** Python application containing core logic. It runs as an `arq` worker to process search queries, interacts with AI models and search providers, and writes results to the database and Redis for the client/Warden to fetch.
- **Location:** `searchboost_service/searchboost_src/`
- **Dependencies:** `arq`, `pydantic`, `httpx`, `sqlalchemy`, `asyncpg`, `openai`, `ollama`.
- **Dependents:** Warden (indirectly via Redis)

### SearchBoost Client (main.py)
- **Purpose:** A command-line client that acts as the entry point for users. It routes requests through the Warden HTTP interface and polls for results.
- **Location:** `searchboost_service/main.py`
- **Dependencies:** `httpx`, local `searchboost_src` modules.

## Data Flow
1. **Client Request:** `main.py` initiates an HTTP request to the Warden's relay port.
2. **Job Enqueue:** The Warden validates the request, checks its circuit breaker, and enqueues the job into Redis.
3. **Processing:** The Python Worker polls Redis, picks up the job, and executes the semantic search pipeline (SearXNG for web results, Ollama/OpenAI for LLM summaries).
4. **Storage:** Results are written to the Postgres database and back to Redis.
5. **Retrieval:** The client polls the Warden's results endpoint (which pulls from Redis) and displays the final answer.

## Integration Points
| External Service | Type | Purpose |
|------------------|------|---------|
| Redis | Queue & KV | Job coordination between Warden and Worker |
| Ollama | AI API | Local LLM inference |
| SearXNG | Search API | Meta-search engine for retrieving web results |
| PostgreSQL | Database | Persistent storage of search history and results |
| Docker Daemon | API | Observed by Warden (`bollard`) for telemetry |

## Conventions
- **Naming:** Rust uses standard `snake_case`, while Python strictly follows standard PEP8.
- **Structure:** `searchboost_src` is structured functionally (`api_client`, `database`, `ai_handler`, `worker`). `searchboost_warden` is similarly split (`relay.rs`, `observer.rs`, `breaker.rs`).
